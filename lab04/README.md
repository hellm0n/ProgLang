*Объясните работу фрагмента программы на С++. В ходе объяснения следует использовать таблицу кодов символов.*
```
char a = 'a';
a = a + 10;
std::cout << a;
a = a + 250;
std::cout << a;
```

**Ответ:**
1. `char a = 'a';` — переменная получает ASCII код символа `a`, то есть 97
2. `a = a + 10;` — код становится 97 + 10 = 107. По таблице ASCII это символ `k`
3. `a = a + 250;` — код становится 107 + 250 = 357, происходит переполнение типа `char`. 357 - 256 = 101 - по таблице ASCII код 101 - это символ `e`

### Задание 4 **(2)**

*Перепишите программу из предыдущего задания на Python, используя функции* **chr** и **ord**.
*Почему ее вывод отличается от вывода программы на С++?*

**Ответ:**
```python
a = 'a'
a = chr(ord(a) + 10)
print(a, end='')
a = chr(ord(a) + 250)
print(a, end='')
```
**Причина отличия:**

В C++ тип `char` это 1 байт и при сложении происходит переполнение. В Python строки и числа имеют неограниченную точность, переполнения не происходит. Функция `chr(357)` выводит символ юникода с этим порядковым номером `団`

### Задание 5. **(2)**

*Объясните работу фрагмента программы на С++. В частности, почему* $x+x-x=x$, *но при этом*
$(x\cdot 2)/2\neq x$? *В отчете надо привести вычисления, приводящие к ответу.*
```
unsigned short x = 40000;
unsigned short y = x + x;
unsigned short z = x * 2;
y = y - x;
z = z / 2;
std::cout << y << " " << z << std::endl;
```

**Ответ:**
Тип `unsigned short` имеет диапазон значений от 0 до 65535
1. `x + x` = 40000 + 40000 = 80000. Происходит переполнение, 80000 - 65536 = 14464. `y - x` = 14464 - 40000 = -25536. Отрицательное число переводится в unsigned: -25536 + 65536 = 40000
2. `x * 2` = 40000 * 2 = 80000. С учетом переполнения `z` становится 14464. `z / 2` = 14464 / 2 = 7232

### Задание 8 **(2)**

*Найдите результаты вычисления следующих выражений без использования компьютера
или калькулятора. Процесс вычислений должен быть отображен в отчете.*
* `(1000 & 100) << 10`
* `(1000 >> 4) & 15`
* `~1234 + 1234`
* `(1000 ^ 500) & 63`
* `(100 << 3) + (100 >> 3)`

**Ответ:**
* `(1000 & 100) << 10`: 
  1000 = 1111101000_2, 100 = 1100100_2. & дает 1000100_2 = 68. Сдвиг влево на 10 бит `68 << 10` эквивалентен 68 * 1024 = 69632
* `(1000 >> 4) & 15`: 
  1000 / 16 = 62. 62 = 111110_2. 15 = 1111_2. & оставляет только 4 младших бита: 1110_2 = 14
* `~1234 + 1234`: 
  Побитовое НЕравно `-x - 1`. Поэтому -1234 - 1 + 1234 = -1
* `(1000 ^ 500) & 63`: 
  63 = 111111_2. Операция `& 63` выделяет только эти 6 бит. Посмотрим на 6 младших бит чисел: у 1000 это 101000_2, у 500 это 110100_2. Их XOR: 101000 ^ 110100 = 011100_2 = 28
* `(100 << 3) + (100 >> 3)`: 
  `100 << 3` - это 100 * 8 = 800. `100 >> 3` - это 100 / 8 = 12 (остаток отбрасывается). Сумма: 800 + 12 = 812
